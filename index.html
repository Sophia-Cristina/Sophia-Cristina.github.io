NEW IDEAS WHILE DEVELOPING THIS WEBSITE:
My website is organized as a modular JavaScript software ecosystem, inspired by the idea of a JS-based operating system. Instead of treating each application as an isolated program, the website is structured so that programs can reuse and build upon other programs. Lower-level components provide functionality to higher-level software, creating a hierarchy similar to the relationship between libraries, utilities, applications, and the operating system itself.

JSHeaders
The lowest-level layer of the system. JSHeaders contains reusable JavaScript classes, functions, and other fundamental components. They are not applications by themselves; they are building blocks that other programs can import and use.

Used by:
JSUtils
The utility layer. JSUtils combines JSHeaders into small, functional programs such as calculators, plotters, mathematical tools, logic tools, and other interactive utilities.
These programs can be used directly, but they are also intended to be reusable components for higher-level applications. In this sense, JSUtils is similar to a collection of system utilities in an operating system.

Used by:
SmallApps
SmallApps combine multiple JSUtils and JSHeaders into applications designed for a particular purpose. A SmallApp may itself become a component that can be reused by a larger application.
For example, a Signal Processing application could combine mathematical, trigonometric, plotting, and signal-processing utilities from JSUtils rather than implementing all of those functions from scratch.

Used by:
BigApps / StudyApps / MiscApps
The higher-level applications of the system. These applications can combine SmallApps, JSUtils, and JSHeaders to create more complex software.

BigApps
Large applications intended to function as complete pieces of software. They may contain many components and depend on numerous lower-level programs.

StudyApps
Applications designed specifically for studying, experimenting with, or demonstrating concepts from particular fields. They use the same underlying software ecosystem, but their purpose is educational or experimental.

MiscApps
Other applications that do not necessarily fit into the previous categories can still use the same architecture. The hierarchy is based primarily on software dependencies rather than on forcing every application into a fixed category.

The basic architecture is:

JSHeaders
|
V
JSUtils
|
V
SmallApps
|
V
BigApps / StudyApps / Other Apps

The important part is that these are not merely separate pages. They are interconnected pieces of software. A higher-level application can import functionality from a lower level, and a program that was originally created as a standalone tool can later become a component of another application.
This creates a structure somewhat analogous to an operating system: fundamental components provide functionality to utilities, utilities provide functionality to applications, and applications can themselves become components of larger software.
The long-term idea is to make JavaScript function less like isolated code attached to individual webpages and more like a modular software environment. The website becomes a place where programs can be composed from other programs, reused, extended, and combined into increasingly complex applications.

INSPIRED BY THE WORKS I'M DOING HERE, I MAY INVENT A NEW SYSTEM FOR THE INTERNET:
I decided to extrapolate the idea above. The idea above was about how my website in specific may behave like an OS. If you think in Computer Science terms, an OS is not "Linux", or "Windows", it is a software that translates the hardware to something humans can understand, and change the machine state by giving an interface for human inputs and machine outputs. If you think in this sense, software to operate electronic signal, then if you see the internet as a system, the data running in the Ethernet cable as electronic signal, then something that translates it and gives an interface for humans would be akin to an "Internet OS". And we already have lot of tools for it: JavaScript, HTML, Browser and etc.

After ideas and deliberations, i decided to call such system an Internet Operational Environment. This is not a "JS based OS", but a protocol to translate what we already have online. There is simple too many apps, and it is energetic not-optimal to require specific websites for small apps, both for the user and the server. If there was a protocol to treat JS scripts as apps, we can reduce this burden by calling codes like an OS app in the browser and using HTML as a "terminal".

This is very short and confusing, and i think people may say there is already systems like this, but i have not found, i found systems that gets close to such idea, but not as i envisioned.
At the list of content of this website, there will be a link to the 'Internet Operational Environment' page. Since i'm going to link an article about the idea and code a proof-of-concept.
