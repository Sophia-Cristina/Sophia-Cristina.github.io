~*~ NETSHELL ~*~

NetShell is the interface through which users interact with the IOE protocol. And this page is its environment.
Since this project is designed primarily as a terminal and TUI, it can be compared to a text-based shell in a traditional operating system. In that analogy, NetShell occupies a role similar to the command-line environment provided by systems such as MS-DOS: it provides the user with a practical interface through which the underlying system can be operated, while the IOE protocol takes the analogous role of the underlying system layer (kernel).
This project is not merely a demonstration or proof-of-concept. NetShell is intended to be the first simple implementation of an interface for the IOE project.

My objective is to maintain the development of this software and make it genuinely useful. At the same time, simplicity is an intentional design principle. The TUI reflects this principle by providing a straightforward way to interact with IOE without requiring a complex graphical environment.
This separation also serves another purpose: it demonstrates what can be accomplished with a minimal interface for the IOE protocol while leaving room for others to develop more modern, graphical, or otherwise more complex interfaces if they choose to do so.

Just as new systems commonly provide official tools for interacting with it, NetShell provides an official and practical way to explore and operate IOE. The purpose is not to leave the IOE protocol as an abstract specification without a convenient means for users to experience it.
By providing NetShell as open-source software, I am establishing a simple reference implementation through which IOE can be explored, while also providing a foundation from which other types of interfaces can be developed. Because I develop IOE alongside NetShell, the interface can follow changes to the protocol and expose new IOE capabilities as they are introduced.
Therefore, NetShell's simplicity should not be confused with a lack of capability. Its purpose is to provide a minimal interface without artificially limiting what can be done through IOE. It should serve as a practical reference for the capabilities of the IOE protocol, regardless of what other interfaces may eventually be built upon the same concepts.

I will not repeat the material already covered in the IOE documentation here. If you want to understand the motivation, architecture, and purpose of NetShell and IOE in greater detail, please read:

I also provide a reference document for NetShell, which can additionally serve as a technical manual. However, it is not intended as a general-user manual or a complete introduction for non-technical users. It is primarily a coding and implementation reference for developers working with NetShell.

With that said, you can use NetShell below.
Please keep in mind, however, that the current implementation is specifically configured to operate with this website. Certain resources are therefore hardcoded into the website itself rather than into NetShell, such as the current directory tree.
If you require a different configuration, you can copy the source code of this page and modify only the parts necessary for your intended use. This allows you to adapt NetShell for local use or another website without having to implement the entire interface from scratch. For example, you could replace the existing directory tree with one corresponding to your own environment.
This is intentional, Netshell is blind about the:
  • Source of the commands;
  • Source of the apps;
  • Source of the directory tree.
It is made this way for modularity sake.
